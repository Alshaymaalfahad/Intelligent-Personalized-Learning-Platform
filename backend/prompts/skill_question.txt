# Workplace realism (required)

Set the question inside a realistic situation at a digital / technical solutions company, the kind of thing an employee actually faces in the first year: a client request, a ticket or user story, a sprint task, a code review comment, a production incident, a failing pipeline, a deadline, a handover from a colleague, a security alert, a data request.
- Hard and soft skills together: hard-skill questions may include a touch of teamwork or client context, and soft-skill questions are always set in the technical work of this specialization (e.g. explaining an integration delay to a client, not a generic office conflict). The correct answer must hinge on the target skill.
- Use realistic but generic names (no real companies or people). Do not literally repeat "at a digital solutions company" in every question — let the situation make the setting clear, and vary roles, clients and project types.

# Keep it short (required)

The trainee should be able to read and answer in about one minute, without planning or long calculation.
- `question_text`: at most ~60 words (2–4 short sentences). Only the details needed to answer.
- Each option: one short line (at most ~15 words).
- `code_snippet` (only if it helps): at most 12 lines.

# Question types

- `scenario`: a short workplace situation; the trainee picks the best action or decision (4 options).
- `true_false`: one clear statement about the right way to act or decide in a short workplace situation. `options` must be exactly ["صح", "خطأ"]; `correct_option_index` 0 = true, 1 = false. Use {{tf_hint}} as the correct answer for this one. No absolute words used as hints, no double negatives.
- `ordering`: the trainee orders 4–5 short steps of a workplace procedure or response (e.g. handling an incident, rolling out a change, responding to a client escalation). Put the steps in `options` IN THE CORRECT ORDER (the server shuffles them); `correct_option_index` = -1. The order must be unambiguous: an expert would agree on exactly one sequence.
- `error_detection`: a short code snippet / query / config / message / plan with one real mistake; the trainee picks the correct diagnosis or fix (4 options). For soft skills the "artifact" can be a short client email or status update.
- `multiple_choice`: a direct applied question, e.g. "which change fixes…", "what is the best reply…" (4 options).

# Quality rules

1. Measure exactly the given skill at the target difficulty — nothing unrelated.
2. Self-contained: everything needed to answer is in the question text or the code snippet.
3. Exactly one option is defensibly correct; a domain expert must agree without debate.
4. Each distractor reflects a real, common mistake made on the job — not an obviously silly choice.
5. All options have similar length, detail and style; the correct option must NOT be the longest or most detailed.
6. For 4-option questions, place the correct option at index {{correct_index_hint}} (0-based).
7. Never use "all of the above", "none of the above", or combined options.
8. No trick questions, double negatives, or ambiguous wording; no unnecessary cultural assumptions.
9. Code snippets: valid syntax except for the intended mistake, in a language or tool commonly used for this specialization. Put code ONLY in `code_snippet`, never in `question_text`.
10. `question_text` must not mention the skill name, the difficulty, or that this is a follow-up question.

# Fields

- `question_type`: exactly the type given above.
- `learning_objective`: one specific, measurable objective.
- `options`: 4 options (scenario, error_detection, multiple_choice); ["صح", "خطأ"] (true_false); 4–5 steps in the correct order (ordering).

- `scoring_rubric`: empty list.
- `reference_answer`: the correct answer plus one sentence on why (for ordering: the correct sequence and the key reason for it).

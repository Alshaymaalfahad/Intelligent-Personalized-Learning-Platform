# The task

- Level 1: a new task. Level 2: a SURPRISE UPDATE to the level-1 task (see previous levels: task_subject, task_message, criteria): the same sender (or a colleague) writes "Update: …" changing the requirements the way real work changes (a new data source, a deadline moved, a stakeholder's new constraint). The acceptance criteria must be the FULL updated list (keep what still applies, add or change 1–2). The boss level: a NEW task in a different situation.
- `sender_name` / `sender_role`: e.g. "Ms. Sara" / "Marketing Manager" (or a client).
- `subject`; `message`: a short, realistic email or chat message (at most ~120 words) with the request and its context.
- `input_title` / `input_lines`: the material to work with (data rows with " | ", notes, a log, a short spec); 0–12 short lines.
- `deliverable_instructions`: exactly what to submit in writing (e.g. a reply to the client, a short plan, a list of issues found with fixes, a prioritized backlog, a test plan). It must be writable in 5–15 lines — no files.
- `acceptance_criteria`: 3–5 specific, checkable criteria (1–3 points each) tied to the competency, as a real manager would state them.
- `hints`: 2 progressive hints.
- `model_answer`: the elements a strong deliverable contains (used by the reviewer; shown to the trainee only after the level).
- For a SOFT-skill competency the deliverable tests the behavior itself (e.g. how they reply to a client asking for out-of-scope work under a deadline), still inside technical work of the specialization.
